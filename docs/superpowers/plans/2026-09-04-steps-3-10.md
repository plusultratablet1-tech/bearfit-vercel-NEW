# BearFit Steps 3–10 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete BearFit Steps 3–10: auditable Bearforce history and season/tier presentation, polished rewards, configurable real package pricing with safe QA cleanup, and production-facing session labels that preserve existing package eligibility.

**Architecture:** Keep PostgreSQL/RPCs authoritative for points, redemptions, package rules, scheduling, and check-in. Add narrow read/update RPCs and additive columns only, then surface them through new member/staff pages while preserving existing internal service categories (`fitness`, `pilates_group`, `pilates_1on1`). Session labels are a separate validated presentation field propagated through scheduling → booking → check-in → activity.

**Tech Stack:** Next.js 16 App Router, React 18, TypeScript, Tailwind CSS, Supabase PostgreSQL/RLS/RPCs, Node built-in test runner.

**Spec:** `docs/superpowers/specs/2026-09-04-steps-3-10-design.md`

## Global Constraints

- Full24, Full48, and Partial24 standard prices remain NULL until BearFit supplies real amounts.
- Real Pilates prices: PILATES5 ₱4,450; PILATES10 ₱8,900; PILATES20 ₱16,400; PILATES1ON1 ₱1,600.
- JJ / M0001 remains the permanent QA/demo member; do not delete its historical accounting/reward/session data.
- Existing Bearforce earning, spending, season, prestige, tier, streak, and reward reservation rules do not change.
- Internal package categories stay exactly `fitness`, `pilates_group`, `pilates_1on1`.
- Production labels stay exactly: Strength Training, Weight Training, Boxing, Conditioning, Cardio, Group Fitness, Pilates Group, Pilates 1-on-1.
- Members never directly mutate progression ledgers, package definitions, reward accounting, or taxonomy fields.
- Do not fabricate historical specific workout labels for legacy rows.
- Service worker must not cache private member/payment/reward/progression API data.
